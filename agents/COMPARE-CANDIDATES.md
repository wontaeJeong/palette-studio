# OpenCode 작업지시 · 실제 앱에서 후보 비교

Superpowers는 이미 활성화한 상태입니다. `design/palette-studio/`를 디자인 레퍼런스로 사용해 우리 앱에 어울리는 후보를 비교해 주세요. 기존 컴포넌트와 폰트·상태 의미를 재사용하세요.

후보는 세 개로 좁혀 주세요. 차분한 **Graphite / Plum**, 중립적인 **Slate / Blue 또는 Slate / Indigo**, 앱 성격에 맞는 **Teal / Sage / Warm 계열 중 하나**를 출발점으로 삼습니다. 기존 앱 색상·서비스 목적 때문에 다른 후보가 더 적절하다면 근거를 붙여 바꿀 수 있습니다.

팔레트 비교 중에는 레이아웃·스타일·샘플 데이터를 고정해 주세요. 동일 화면에서 색상 차이를 먼저 봅니다. 대표 화면은 다음과 같습니다.

- 실제 운영 목록: 긴 항목 이름·한국어 설명, 필터, 검색, 정렬, 페이지네이션, 선택 행과 여러 상태가 공존하는 화면.
- 상세 화면: JSON 코드, 긴 설명·오류 메시지, 여러 상태, 복사 버튼, 긴 스크롤이 공존하는 화면.
- 예외 상태: 권한 없음, 데이터 없음, 로딩, 재시도 가능한 실패, 입력 오류.

기존 앱은 사용자가 지정한 테마 변경 범위 안에서 비교하고, 새 앱은 두 모드를 비교합니다. 팔레트마다 새 UI를 만들지 말고 같은 컴포넌트의 테마만 바꾸세요. 미리보기 키트의 샘플은 실제 앱의 대체물이 아닙니다.

비교 결과는 같은 뷰포트·데이터·상태로 남겨 주세요. 핵심 정보 식별, 상태 의미, 포커스와 코드 가독성, 밀도와 긴 문자열, 기존 브랜드 일관성 관점에서 구체적인 차이와 추천 후보를 적습니다. 점수가 필요하면 근거가 있는 짧은 평가로만 쓰고 임의의 과학적 점수로 포장하지 마세요.

채택 전 후보 탐색 범위와 실제 제품 적용 범위를 구분해 결과를 남깁니다. 사용자가 이미 팔레트를 선택했다면 비교를 반복하지 말고 `APPLY-PROFILE.md`로 진행하세요.
