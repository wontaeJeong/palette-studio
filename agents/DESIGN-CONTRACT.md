# 선택한 디자인의 적용 계약

이 파일은 앱에 채택한 스타일을 일관되게 유지하는 규칙이다. 앱의 기능·구조·기술 스택을 새로 설계하라는 지시가 아니다.

- 선택된 `design-profile.json`의 palette, style, designSelection.concept, target, scope가 적용 기준이다. 팔레트와 스타일은 독립적으로 고를 수 있다.
- 기존 앱의 컴포넌트를 재사용한다. CSS 키트의 예제를 그대로 옮기기 위해 동일 역할의 새 컴포넌트를 만들지 않는다.
- 의미 토큰은 literal `#RRGGBB`로 정의하고 한 토큰/한 모드의 canonical 정의를 하나만 둔다. 사용 속성은 `var(--color-...)`로 연결한다.
- `dark-only`면 기존 라이트 색상을 그대로 둔다. 프로필의 전체 팔레트 경로에는 두 모드가 있으므로 다크만 추출하거나 UI에서 scope에 맞게 내보낸 CSS를 병합한다.
- 포인트는 주요 행동·현재 메뉴·선택에 집중한다. 카드 제목·보조 아이콘·모든 배지를 한꺼번에 포인트색으로 칠하지 않는다.
- 현재 메뉴는 accent-subtle 면 + 좌측 표시 + 현재 항목 의미, 선택 탭은 밑줄 + 굵기 + 적절한 ARIA 패턴으로 구별한다.
- 텍스트·입력 경계·포커스는 지정 대비 쌍을 사용한다. 장식 `line`과 입력 `line-strong`을 혼동하지 않는다.
- 코드 블록은 code-bg + code-fg + code-line. 인라인 코드도 경계와 배경을 갖춘다. JSON 값의 실제 타입으로 하이라이트한다.
- PASS/REVIEW/REJECT/실행 실패, 심각도, 선택 상태를 섞지 않는다. 문구·기호·아이콘을 함께 쓴다.
- 기본 버튼·hover·pressed·focus·disabled, 입력 오류·readonly·loading을 빠뜨리지 않는다. 기존 접근성 동작을 유지한다.
- 선택 스타일의 라운드·간격·컨트롤 크기를 화면 전반에 적용한다. Compact도 터치나 접근성 요구 때문에 필요한 크기를 줄이지 않는다.
- 선택 프로필의 fonts 설정을 기존 폰트 로더에 병합한다. CDN 우선이면 동봉 WOFF2·시스템 fallback을 제공하고 원본 저작권·OFL 파일을 유지한다. 영문 중심 폰트의 한글 보완 설정도 유지한다. 폰트는 두 컬러 모드에 공통이다.
- 네온·입체 그림자·장식 그라데이션은 기본 범위에 없다. 명시적으로 선택한 콘셉트의 입체감·재질은 허용하되 기능 위계를 설명해야 한다. Glass는 내비게이션·오버레이 같은 기능 레이어에 별도 장식층과 불투명 fallback을 두며 본문 카드 전체를 투명하게 만들지 않는다. 의미 색상 토큰·대비·상태 의미는 바꾸지 않는다.
- 콘셉트의 `--concept-*` 형태·위계·깊이를 기존 선택자에 연결한다. 스타일은 간격·크기 조정이며 선택한 본문·코드 폰트가 우선한다. 포털에도 `data-theme`, `data-palette`, `data-style`, `data-concept` 범위를 전달한다.
- 검증은 정적 색상 쌍과 실제 화면을 구분한다. 스크린샷으로 클릭·키보드 동작을 검증했다고 주장하지 않는다.

기록은 `agents/DECISION-LOG.template.md` 형식으로 간결하게 남긴다. 실제 앱에서 색상만으로 해결할 수 없는 문제는 해당 화면과 원인을 명시한다.
