# 디자인 도감

`catalog.html`에서 화면 프리셋을 선택하고 요소를 다듬습니다. 기본 팔레트·스타일·본문 폰트·화면 종류와 30종 요소의 추천 표현이 함께 적용됩니다. 색상·형태·여백·밀도의 조합이므로 팔레트 이름만 바꾼 프리셋과는 다릅니다.

## 사용 흐름

1. 여섯 화면 프리셋 중 시작점을 선택합니다. 다른 프리셋으로 바꾸면 직접 선택이 초기화되며 **직전 변경 되돌리기**로 복원할 수 있습니다.
2. ‘저장하면 잠깐 뜨는 알림’, ‘확인창’, ‘여러 개 체크’처럼 역할을 검색하거나 분류로 좁힙니다. 정식 영어 이름과 한국어 설명을 함께 제공합니다.
3. 기본·마우스 올림·키보드 포커스·비활성·입력 오류·처리 중 상태를 입력과 버튼 견본에 적용할 수 있습니다. 이 상태 선택은 QA용 시연이며 디자인 선택 자체를 바꾸지 않습니다. 중립 표면 / 부드러운 면 / 강조 테두리를 나란히 보고 선택합니다. 모서리·여백·테두리·색상 역할이 달라집니다. 최대 세 후보를 비교할 수 있습니다.
4. 대시보드·설정·문서·랜딩 화면에서 조화를 봅니다. 그 화면에 실제 배치된 요소의 선택만 해당 미리보기에 나타납니다. 나머지 요소는 도감 자체에서 확인합니다.
5. **작업지시 만들기**에서 적용 범위·프레임워크·코드 폰트 등을 확인하고 JSON·CSS·프롬프트를 내보냅니다. 기존 앱의 적용 의도와 범위는 보존합니다.

화면과 도감은 오프라인 정적 견본입니다. 입력·선택·펼침·확인창·패널·알림은 동작 시연이며 백엔드에 저장하지 않습니다. 원시 메뉴와 탭 견본은 native details와 버튼으로 조작을 보여줍니다. 실제 앱에서 요구되는 전체 ARIA menu/tab 키보드 구현은 각 요소의 동작 기준과 작업지시에 명시합니다. 브라우저별 native datalist의 표현은 다를 수 있습니다. 견본만으로 전체 접근성 준수가 인증되지는 않습니다.

선택은 `palette-studio-catalog-v1`에 로컬 저장합니다. 직전 변경과 비교 후보는 현재 세션에서만 유지합니다. 링크에는 선택을 포함하며 별도 서버에 업로드하지 않습니다. 저장소가 차단되면 링크로 작업지시에 전달하고 JSON으로 보관하세요. `START-HERE.html`의 단독 실행 팔레트 기능은 유지하며 새 도감은 키트 폴더 내의 별도 파일입니다.

## 디자인 구성 근거

2026-11-14 기준 다음 공식 자료의 구성 원칙과 동작 정의를 참고했습니다. 외부 코드를 복사하거나 특정 라이브러리를 의존성으로 추가하지 않았습니다.

- [shadcn/ui 공식 저장소](https://github.com/shadcn-ui/ui): 완성된 선택을 출발점으로 사용하면서 직접 확장·수정하는 컴포넌트 접근 방식.
- [Radix Dialog](https://www.radix-ui.com/primitives/docs/components/dialog): 포커스 관리, 모달, Escape 등 확인창의 동작 정의. 공식 저장소의 현재 문서를 확인했습니다.
- [Radix Toast](https://www.radix-ui.com/primitives/docs/components/toast): 사용자 작업과 연결되는 일시적 알림의 동작 정의. 공식 저장소의 현재 문서를 확인했습니다.
- [WAI-ARIA 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/): 실제 앱에서 검증할 키보드·역할 기준.

‘차분한 업무형 / 부드러운 제품형 / 선명한 테두리형 / 타이포 중심형 / 조밀한 운영형 / 대담한 브랜드형’은 이 키트의 큐레이션 이름입니다. 이 여섯 조합이 시장 점유율 상위이거나 최신 유행임을 통계적으로 확인한 것은 아닙니다. 유행 순위 대신 목적·밀도·타이포·형태를 기준으로 선택하도록 구성했습니다.

## 공통 데이터와 검증

`data/component-catalog.js`가 견본과 JSON·문서·작업지시의 단일 레지스트리입니다. 선택은 `designSelection: { preset, overrides }`이며, 프로필에는 완전히 펼친 `componentRecipes`가 포함됩니다. CLI와 브라우저는 `data/handoff-core.js`의 같은 생성기를 씁니다. 이전 설정에 `designSelection`이 없어도 정상 작동합니다.

```bash
node scripts/test-component-catalog.cjs
NODE_PATH=/workspace/palette-qa/node_modules node scripts/browser-runtime.cjs scripts/check-component-catalog.cjs
```

기본 브라우저가 file://를 지원하는 환경에서는 `node scripts/check-component-catalog.cjs`로도 검사할 수 있습니다. 관리형 Chromium은 QA 전용 `browser-runtime.cjs`로 로컬 HTTP에서 같은 파일을 검사합니다. 이 실행기는 외부 페이지 요청을 허용하는 설정을 추가하지 않으며 프로덕션에 포함되지 않습니다.
