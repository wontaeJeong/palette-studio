# 공통 앱용 Palette Studio

사용자의 다섯 요구사항: 특정 앱에 종속되지 않는 예시, 스크롤 중 유지되는 미리보기, 선택 이후 내보내기, 전반적인 UI 개선, 본문·코드 폰트 분리.

## 설계

- 기존 HTML/CSS/JavaScript와 팔레트·폰트 로더를 사용한다. 라이브러리·서버는 추가하지 않는다.
- 공통 프로젝트 대시보드를 예시로 사용한다. 새 앱과 두 테마를 기본으로 제공하고, 기존 앱에는 변경 범위를 명시적으로 선택하게 한다. 이전 `existing-gate` 링크는 `existing-app`으로 이관한다.
- 색상 → 스타일 → 폰트 → 확인·내보내기의 네 단계를 자유롭게 왕복한다. 선택은 단계 이동·새로고침 후에도 유지한다. CSS·프로필·작업지시 저장은 마지막 단계에만 배치한다.
- 큰 화면은 좌측 선택·우측 sticky 미리보기다. 미리보기 내부를 별도로 스크롤한다. 작은 화면은 하단 고정 미리보기와 확대/축소 버튼을 제공하고 콘텐츠가 가려지지 않게 여백·포커스 스크롤을 확보한다.
- 폰트는 본문 15종과 코드 9종을 별도 제목·검색·카드 영역으로 분리한다. 각 역할에 선택된 폰트를 문구와 버튼 상태로 표시한다. 한 역할 변경이 다른 역할을 변경하지 않는다.
- 선택 요약, 현재 단계, 검색 결과 없음, 명확한 선택 상태, 키보드 포커스를 제공한다. 컴포넌트·토큰은 선택을 돕는 상세 자료로 둔다.

## Approaches

기존 한 페이지에서 위치만 변경하면 긴 폰트 목록과 빠른 내보내기가 섞이는 문제가 남는다. 전면적인 프레임워크 전환은 이 요구에 불필요하다. 기존 상태·내보내기를 유지하면서 단계별 선택기와 미리보기 레이아웃을 추가하는 방식을 구현한다.

## 수용 기준

360/390/768/1440px에서 페이지 가로 넘침이 없다. 선택 목록 끝에서도 적용 미리보기를 볼 수 있다. 32개 팔레트, 64개 테마, 6개 스타일, 24개 폰트, OFL 고지, CDN·오프라인 폴백은 유지된다. 단독 HTML과 모듈 원본의 동작이 같다.
