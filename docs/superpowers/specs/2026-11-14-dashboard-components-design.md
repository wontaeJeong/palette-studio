# Dashboard component preview design

User authorized implementation, PR creation and merge on 2026-11-14 after the proposed scope. Existing 19 components become 47 searchable, selectable components. Preserve six starter sets, nine concepts, palette comparisons, light/dark modes, scope restrictions, shared browser/CLI output and offline execution.

## Scope
Add bar-chart, stacked-bar, line-chart, area-chart, donut-chart, pie-chart, histogram, scatter-chart, heatmap, sparkline; metric, progress, circular-progress, stepper, skeleton, spinner, error-state; radio, textarea, slider, date-picker, file-upload, combobox; data-table, avatar, timeline, list, separator.

Each component supports the existing soft/outline/solid surface treatments. Data series retain distinct categorical colors, progress retains progress tokens, errors retain error semantics. Chart series follow the selected palette; heatmap uses a sequential scale with readable value labels. All semantic tokens remain literal HEX generated by scripts/build.py. No new runtime dependency or external request.

## Approaches
The presented scope was accepted with delegation of implementation details. Extend the existing catalog and shared handoff generator, and reuse a dedicated HTML/SVG demo renderer in component details and the dashboard (chosen). A preview-only addition would not preserve choices in exports. A new chart library would add runtime and licensing work without improving fixed sample previews.

## Experience
Keep the single workspace and existing project/settings navigation. Add a dashboard section in project preview with KPI, bar/line/donut charts and progress. The component catalog holds the full collection with search/category filters and paired modes. Readable chart axes, legends, direct values and expandable data tables convey meaning beyond color. Use native form controls; enhanced samples implement sorting/filtering, slider readouts, file feedback, step progression and retry states. Motion obeys reduced-motion preferences.

No marketing copy. Preserve untracked .serena in main and other worktrees. Implementation, tests and commits only in the managed feature worktree. Test legacy selection normalization, invalid IDs, browser/CLI parity, isolated light/dark interactions, all 47 families at mobile and desktop across concepts, palette contrast, file:// and bundled START-HERE.html. Existing app/library/navigation checks remain passing. No claim of whole-app accessibility certification or universal component completeness.
