# Palette Studio의 React·TypeScript 단계적 전환

상태: 2026-11-14 사용자 승인. 이 문서는 승인된 전환 범위와 호환 조건을 정의한다.

## 목적과 판단

팔레트·콘셉트·글꼴·메뉴·아이콘·UI 라이브러리 선택을 하나의 설정으로 관리하고, 미리보기·공유·내보내기가 같은 결과를 사용하도록 유지보수 구조를 개선한다. 현재 통합 작업실의 사용 경험과 기능은 유지한다. 작업실 자체의 React 사용은 대상 앱에 React를 강제하지 않는다.

사용자가 선택한 방향은 React·TypeScript 기반 프런트엔드와 정적 배포다. 로그인·DB·서버 저장·협업은 이번 범위에 없다. UI 재디자인, 신규 컴포넌트 추가, 기존 대상 앱의 프레임워크 변경도 포함하지 않는다.

초기 기준은 main의 b2f9aa7이다. 다른 worktree의 진행 중 기능은 포함하지 않는다. 구현 전에 main이 갱신되었다면 변경 범위를 다시 비교해 별도 작업을 덮어쓰지 않는다.

## 검토한 접근

1. **Vanilla JS 정리만 수행:** 전환 비용은 가장 작다. 다만 catalog/workspace의 직접 DOM 갱신과 이벤트 연결을 계속 관리해야 한다.
2. **React·TypeScript로 단계적 전환 — 사용자가 선택:** 기존 데이터·CSS·생성기·검증을 재사용하며 상태와 UI의 책임을 분리한다. 기존 링크와 오프라인 호환을 별도로 검증해야 하는 비용이 있다.
3. **서버와 DB를 포함한 서비스 전환:** 계정별 동기화·팀 권한이 요구될 때 검토한다. 현재 확인된 요구에는 운영 부담을 정당화할 기능이 없다.

빌드 도구는 기존 실제 라이브러리 미리보기에 사용하는 esbuild를 재사용하는 것을 제안한다. 앞선 대화의 Vite는 가능한 예시였으며 도구 교체 자체가 목표는 아니다. React·TypeScript 버전은 저장소의 잠금 파일에서 확인한 버전을 기준으로 고정한다.

## 완료 범위와 단계

아래 세 단계를 각각 검증 가능한 변경 단위로 진행한다. 이 설계 전체의 완료는 세 단계가 모두 통과한 시점이며, 상태 모듈만 추가하고 전체 전환을 완료했다고 보고하지 않는다.

### 1. 타입과 선택 상태의 분리

- 기존 handoff-config와 design-profile의 JSON 형식·필드명·기본값을 유지한다. 전환을 위한 불필요한 버전 변경을 하지 않는다.
- `data/handoff-core.js`의 정규화와 출력 생성 함수를 canonical 원본으로 유지한다. 이 단계에서는 생성 로직 전체를 TypeScript로 다시 쓰지 않고, 정확한 타입 경계와 컴파일 검사를 추가한다.
- DOM에 의존하지 않는 TypeScript 선택 store를 도입한다. 정규화를 통과한 설정만 저장하며, 잘못된 변경은 이전 설정을 유지하고 오류를 호출자에게 돌려준다.
- 일반 설정 변경은 기존 필드를 유지한다. fonts와 designSelection의 부분 변경은 관련 형제 필드를 보존하며, 프리셋 선택에 따른 기본값 적용·개별 표현 초기화는 별도 명시적 동작으로 관리한다. 현재 세트 선택의 적용 범위를 회귀 검사로 고정한다.
- 공유 URL 읽기·직렬화, localStorage 읽기·저장, 이전 설정 복원은 독립 경계로 분리한다. 선택 전체가 있는 URL이 저장값보다 우선하고, 이전 단일 필드 링크의 적용 순서도 현재 동작을 유지한다.
- 도구 라이트/다크, 비교 모드, 미리보기 활성 페이지, 검색어, 다이얼로그, 유효하지 않은 프로젝트 이름 초안은 내보내는 디자인 설정과 구분한다. 현재 공유되는 비교 보기 옵션은 URL 왕복을 유지한다.
- 차단되거나 손상된 저장소에서도 편집·미리보기·내보내기는 동작한다. 검색어·지표·임시 입력이 프로필로 유출되지 않는다.
- 전환 중 `PaletteCatalog.getConfig/update/readyFonts`, `PaletteWorkspace.outputs/shareURL`, `PaletteStudio.profile/selectedCSS/fontCSS/readyFonts`와 기존 selection 이벤트를 호환 어댑터로 제공한다. 별도의 상태 원본을 만들지 않는다.

### 2. 통합 작업실을 React 화면으로 전환

- 루트 `index.html`의 통합 작업실을 React·TypeScript 진입점으로 전환한다. 주요 책임은 작업실 골격, 선택 패널, 프로젝트 미리보기, 확인·내보내기, 실제 라이브러리 영역으로 나눈다.
- 기존 한국어 문구, 기능, CSS 선택자, 토큰, 폰트 로더, Lucide 자산을 우선 재사용한다. 단일 작업실과 고정 미리보기, 모바일 확대 동작, 확인 단계에만 있는 다운로드를 유지한다.
- `catalog.js`와 `workspace.js`의 전역 렌더 루프를 통합 작업실에서 제거한다. 레거시 독립 화면은 필요한 기존 코드를 계속 사용할 수 있다.
- React가 소유하는 DOM에는 외부 코드가 innerHTML을 쓰지 않는다. 아직 유지하는 데모 런타임은 명시적 경계 안에서만 DOM을 소유하고, 마운트·갱신·해제 수명을 갖는다. 통합 작업실 전체를 문자열 HTML로 감싸는 전환은 완료로 보지 않는다.
- 실제 라이브러리 TSX 어댑터를 재사용하고, 편집기와 같은 React 런타임에 연결한다. 기존 독립 실행용 번들은 레거시 화면용으로 유지하되 새 작업실에서 중복 로드하지 않는다.
- 툴팁·메뉴·모달·드로어·팝오버·토스트의 키보드, 포커스 복귀, 타이머, 포털 범위와 cleanup을 보존한다. unrelated 설정 변경으로 검색 입력·미리보기 페이지·유효하지 않은 이름 초안이 사라지지 않아야 한다.
- 지표 새로고침은 기존 명시적 동작과 캐시를 유지한다. 로딩 중 선택 변경, 오래된 응답, 부분 실패가 현재 선택을 덮어쓰지 않도록 한다.
- `catalog.html`, `handoff.html`, `icons.html`은 독립 실행을 유지한다. 레거시 URL 및 브라우저/CLI 출력 호환은 전환 이후에도 검사한다.

### 3. 하나의 소스에서 웹·오프라인 산출물 생성

- 웹용은 `out/web/`에 HTML·CSS·JavaScript·필요 자산을 생성한다. ESM 분할 빌드로 실제 라이브러리 어댑터를 선택 시 로드하고, 기존 폰트 공급 정책을 유지한다. 루트 및 저장소 하위 URL에서 실행할 수 있어야 한다.
- 기존 루트 `index.html`은 classic-script 빌드를 참조해 체크아웃에서 file:// 실행을 계속 지원한다. `START-HERE.html`은 동일 앱 소스를 단일 classic-script 번들·CSS·폰트·라이선스로 합친 오프라인 산출물로 유지한다. 전용 HTML shell은 하나만 관리하고 빌드별 script 삽입을 자동화한다.
- 오프라인 경로에는 네트워크 import·런타임 CDN 스크립트·청크 요청이 없어야 한다. 기존 선택적 폰트 CDN 및 사용자가 요청한 지표 조회 외에는 네트워크를 요구하지 않는다. local-only/system 폰트에서 메트릭 새로고침 전 외부 요청은 0건이어야 한다.
- 웹에서는 선택되지 않은 실제 라이브러리 런타임을 초기 로드하지 않으며, 로드 실패는 한국어 재시도 상태를 표시한다. 선택이 바뀐 뒤 도착한 이전 라이브러리 로드 결과는 현재 미리보기를 대체하지 않는다.
- 기존 `scripts/bundle.py`는 단일 파일 패키징 역할을 유지하도록 연결한다. `scripts/build.py`는 기존 팔레트·스타일 생성 원본으로 유지한다.
- Node CLI는 계속 npm 설치 없이 동작한다. 프런트엔드 개발/빌드 의존성을 CLI 실행 경로에 추가하지 않는다.
- 개발·빌드·typecheck·순수 회귀·브라우저 회귀를 실행할 루트 명령과 잠금 파일을 추가한다. 생성물 드리프트 검사는 빌드 재실행 후 변경이 없는지 확인한다.
- 현재 GitHub Pages의 main 루트 배포 설정은 유지한다. 웹용 out/web 산출물과 배포 방법까지 준비하되, 배포 소스 변경·원격 PR 병합·공개 배포는 이 설계의 구현 범위가 아니다. 구현 결과는 격리 브랜치의 검토 가능한 커밋으로 남긴다.

## 유지할 계약

- 신규 선택은 새 앱 / 라이트+다크. dark-only 및 light-only는 허용한 모드만 출력한다.
- 색상 의미 토큰은 모드별 하나의 literal HEX 정의. 폰트 본문/코드 역할 분리 및 OFL·Lucide 라이선스 유지.
- 상태 문구·아이콘, 키보드 포커스, 링크의 비색상 단서, reduced motion을 유지한다.
- 브라우저·CLI의 같은 설정은 같은 이름과 바이트의 공통 생성 파일을 출력한다. CLI 전용 자산·스키마·manifest는 기존 범위를 유지한다.
- `--check`는 파일을 수정하지 않는다. 기존 설정과 공유 링크를 폐기하지 않는다.
- 사용자가 요청하지 않은 홍보 문구·슬로건·레이아웃 재설계를 추가하지 않는다.

## 검증과 인수 조건

구현에서는 먼저 변경 전 행동을 고정하는 검사와 새 상태·빌드 경계에 대한 실패 검사를 추가한다. 기존 검사를 축소해 전환을 통과시키지 않는다.

1. 상태: 부분 변경·프리셋 초기화·유효하지 않은 입력의 원자성·URL 우선순위·손상/차단 저장소·이전 링크·프로필에 없는 보기 상태를 순수 검사한다.
2. 출력: 기존 handoff/catalog/navigation/concept/library/schema 검사, 범위별 CSS, 브라우저/CLI 공통 파일의 바이트 일치, CLI --check의 무수정성을 확인한다.
3. UI: 작업실 및 폰트 흐름 검사, 독립 화면 회귀, 콘셉트/컴포넌트/메뉴/라이브러리/메트릭 검사를 재사용한다. 필요한 DOM 어댑터 변경은 동등한 사용자 행동 검증을 유지한다.
4. 실행 환경: root index의 file://, 다른 임시 폴더로 복사한 START-HERE의 file://, out/web의 HTTP 루트·하위 경로를 확인한다. 웹 청크의 지연 로드·실패·빠른 선택 변경을 확인한다.
5. 화면: 360/390/768/1440px, Light/Dark 및 비교, 포커스 유지, reduced motion, 폰트 폴백을 확인한다. 기존 캡처와 비교해 의도하지 않은 레이아웃 변화를 수정한다.
6. 빌드: strict TypeScript, 재현 가능한 빌드, 생성물 드리프트, 타사 라이선스, 스크린샷 소스 해시를 확인한다. 캡처 목록에는 새 TS/TSX 원본·설정·잠금 파일·생성물을 포함한다.
7. 성능: 동일한 환경에서 전환 전후 초기 JS 바이트와 로드 요청을 기록한다. 웹 초기 요청에서 선택되지 않은 라이브러리 청크가 제외되는 것을 검증하고, 단일 파일 크기는 별도로 보고한다. 근거 없는 체감 속도 개선을 주장하지 않는다.

독립적으로 실행 가능한 단계별 커밋과 검증 기록을 남긴다. 최종 보고에서 완료된 단계·남은 단계·검증하지 못한 환경을 구분한다. 기본 checkout은 최신 main으로 유지하고 기존 .serena와 다른 worktree 작업을 보존한다.

## 구현자가 결정할 사항

세부 파일 배치, 컴포넌트 이름, 내부 store API, 라이브러리 chunk 분할 방식, 동등한 동작을 보존하는 테스트 보조 함수는 구현 계획에서 정한다. 새 상태 라이브러리는 필요성을 입증하지 않으면 추가하지 않는다. 생성기 TypeScript 전면 이식, 서버 도입, 신규 기능은 후속 범위다.
